# 性能基线

测量日期：2026-07-23
环境：Kiro CLI 2.14.0、Python 3.14、单实例 systemd 用户服务
模型：`claude-haiku-4.5`
并发：1

## 优化前结果

| 请求 | 首字节 | 总时长 | 观察 |
|---|---:|---:|---|
| `/v1/models` 第一次 | 2.657s | 2.658s | 每次启动 `kiro-cli --list-models` |
| `/v1/models` 第二次 | 2.366s | 2.367s | 无缓存 |
| Chat 非流式 | 8.268s | 8.268s | 先查询模型，再启动生成 CLI |
| Chat `stream=true` | 7.737s | 7.737s | 首字节等于总时长，属于完成后单块 SSE |

生成请求包含两个短生命周期子进程：模型发现进程与 `chat --no-interactive` 进程。采样前后未留下子进程，但请求期间存在重复冷启动。

## 验收目标

- 热请求代理固定开销不超过 500ms，不包含模型推理时间。
- 上游首个文本事件产生后 100ms 内转发给客户端。
- 热生成请求不得再启动 `--list-models` 子进程。
